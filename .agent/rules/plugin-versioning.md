# Obsidian 插件版本与更新发布规则

## 适用范围

提交修改前必须检查本次差异是否影响 Obsidian 插件的运行行为、界面、样式、兼容性或打包产物。涉及 `plugin/src/`、`plugin/styles.css`、插件运行依赖、构建配置等实际插件更新时，必须同步维护插件版本，不能只提交功能或 Bug 修复而遗漏版本元数据。

仅文档、测试或不影响插件产物的后端变更，不要求提升插件版本。此规则不授予 Commit、Push、Tag、Release 或其他远程操作权限，仍须遵循用户授权和 Git 安全规则。

## 提交前必须执行

1. 检查当前工作区、版本文件、相关本地标签与已知发布状态，区分已发布版本和正在准备的版本。必要时只读查询远端，不能把旧记录当作当前发布事实。
2. 为插件更新确定高于已发布版本的新版本号，使用 `X.Y.Z` 格式。用户指定版本时遵从用户；未指定时，兼容的 Bug 修复默认提升 patch，功能或不兼容变更按 SemVer 处理。
3. 同一待发布批次内的连续修改可以共用一个已经准备好的新版本；不得为已发布版本替换不同代码，也不必为同一批次的每个中间提交反复升版。
4. 将下面的开发版本元数据与插件修改一并纳入获授权的提交，保持目标版本一致：

   | 文件 | 必须同步的字段 |
   | --- | --- |
   | `plugin/manifest.json` | `version` |
   | `plugin/package.json` | `version` |
   | `plugin/package-lock.json` | 顶层 `version` 和 `packages[""].version` |
   | 根目录 `versions.json` | 新版本到 `minAppVersion` 的映射，保留历史条目 |
   | `plugin/versions.json` | 同步追加该版本映射，保留历史条目 |

5. `minAppVersion` 依据实际 Obsidian API 兼容性决定，不随插件版本机械提升；映射值必须与该版本插件清单一致。官方主要在最低宿主版本变化时要求更新兼容映射，本项目约定每次新版本都追加映射。
6. 在 `plugin/` 使用项目要求的 Node.js 20+，运行 TypeScript 检查、插件测试和生产构建；执行 `git diff --check`。核对版本字段和兼容映射，避免升版造成无关依赖变化。不得把构建产物 `plugin/main.js` 提交到 Git。

## 根目录清单与市场公告

根目录 `manifest.json` 是 Obsidian 社区插件更新的版本入口，本项目的插件更新提示也读取它。它必须指向已经发布、资源可下载的正式版本。

采用两阶段顺序：

1. **准备提交**：更新上表的版本元数据并验证插件。新版本 Release 尚未就绪时，根目录 `manifest.json` 保持最近已发布版本，在交付说明中明确记录“待 Release 验证后更新根清单”。开发版本与公告版本在此阶段允许暂时不同。
2. **发布与公告**：获得相应授权后，按项目发布流程发布新版本并核验资源，再更新根目录 `manifest.json.version` 到该版本。公告完成后，根清单、插件清单、包版本、锁文件版本、兼容映射和 Release 资源版本必须一致。

不得为了满足表面上的版本一致性，提前把未发布版本写入根清单；也不得发布后遗漏根清单更新，导致市场继续看到旧版本。当前 Release 工作流会覆盖资产清单中的版本，不能以此替代提交前维护源码版本元数据。

## 发布完成的必要条件

- 社区插件正式发布使用不带 `v` 前缀的 `X.Y.Z` 标签，与根清单 `version` 完全相同。工作流允许 `v` 前缀或 RC 标签，不代表它们适合作为社区市场正式更新入口。
- GitHub Release 已发布且非草稿、非预发布，包含可下载的 `main.js`、`manifest.json` 和本项目使用的 `styles.css`，资源必须位于 Release 附件中。
- 下载并检查实际发布资源，确认资产清单中的插件 ID、版本和最低 Obsidian 版本正确，核验校验和及实际构建来源。不能仅凭 CI 绿色、标签存在或仓库内清单就声称发布成功。
- 资源核验完成后更新并推送根清单公告提交，检查对应 CI 与远端根清单。没有 Push 或发布授权时，停留在本地准备状态，明确报告尚未完成的公告步骤。
- 只有在上述资源和公告均完成后，才能报告“已满足市场检测与下载更新条件”。未在真实 Obsidian 中检查并安装更新时，不得声称已完成客户端更新验收。

## 依据与源码入口

- [Obsidian 官方发布说明](https://docs.obsidian.md/Plugins/Releasing/Submit%20your%20plugin)：清单版本、匹配标签及 Release 附件要求。
- [Obsidian 官方兼容版本说明](https://docs.obsidian.md/Reference/Versions)：`versions.json` 的兼容回退作用。
- 本项目发布流程：`.github/workflows/release.yml`。
- 本项目插件版本检测：`plugin/src/plugin-update.ts`。
